# 使用说明

1. 在“项目与导入”新建项目。
2. 根据资料选择 OpenAPI、Postman、Apifox、cURL、HAR、文档或 Spring 源码。
3. 查看导入摘要和完整度；文档草稿需要在“接口管理”编辑确认。
4. 在“环境与请求”创建至少一套环境，填写 Base URL、公共 Header 和变量。
5. Token、password、secret 等变量会自动分离并本地加密。
6. 勾选“已授权的测试/预发布环境”后才能发送请求。
7. 在“用例与执行”输入测试要求并预览计划。
8. 模型配置留空时使用离线规则引擎；填写 OpenAI-compatible 配置时使用结构化模型输出。
9. 生成用例后检查 JSON。任何修改都会把用例重置为草稿。
10. 确认用例；POST、PUT、PATCH、DELETE 会再次提示高风险确认。
11. 执行后可停止任务，并实时查看用例结果和进度。
12. 在“历史报告”查看 HTML/JSON 文件路径和执行汇总。

“接口测试”导航分为两条路线：二级目录是路线 A“源码驱动测试”和路线 B“资料驱动测试”，三级目录放置各自的接口、环境、流程、用例等功能；路线 A 用于源码、业务流程、数据流和数据库状态，路线 B 用于 OpenAPI、Postman、cURL、HAR、文档等接口资料。

源码业务流程（路线 A）：

1. 导入后端源码后，进入“业务流程”，点击“生成源码流程草稿”。
2. 检查并编辑步骤、请求参数、响应提取、数据库断言和补偿动作。
3. 选择 SQLite 测试库或副本；只做断言时保持“只读数据库”。
4. 在“测试数据”中保存夹具；需要写入夹具时，必须显式关闭只读并使用测试库。
5. 点击“确认流程”，然后确认测试环境，最后执行已确认流程。
6. 流程失败会按逆序执行补偿动作；每个步骤、数据库结果和补偿结果都会写入审计记录。

当前流程执行器支持 HTTP、SQLite 数据库断言、SQLite 夹具、数据库删除补偿和 HTTP 补偿。
生产数据库、任意 SQL 写入、消息队列和第三方系统的副作用仍需通过专用适配器接入，
不会由源码导入自动连接或修改。

AI 对话：

1. 进入“AI 对话”，选择路线 A、路线 B 或组合模式。
2. 描述业务目标，AI 会列出实体、可见/隐藏工艺、数据流和缺口问题。
3. 审阅结构化草稿和证据引用；审批前不会发送请求、执行 SQL 或调用外部系统。
4. 路线 A 草稿审批后会自动进入“源码驱动测试”，形成 API + 数据库联合测试流程。
5. 系统根据源码写库证据生成关联表的只读前后快照；请审核查询范围和预期状态后再确认流程。
6. 执行时必须同时配置已启动后端的 Base URL 和测试数据库；API 执行后会核对关联表数据变化并将证据回填到内部工艺检查点。
7. 接口响应成功但关键数据库工艺没有观察证据时，结果为 `inconclusive`，不会判定通过。

AI 对话有两个共享入口：

- 完整页面：点击左侧“AI 对话”，使用快捷任务、查看完整对话、测试草稿与证据，并审批生成的路线 A 流程。
- 快捷助手：在任意页面按 `Ctrl+K`，或点击顶部“AI 助手”，从右侧侧栏提问；再次按 `Ctrl+K` 可关闭。

两个入口使用同一个当前项目和同一个会话。右侧助手产生的消息和草稿会同步到完整页面，不会建立第二条独立测试链路。
4. 在“源码驱动测试 · 路线 A”中检查测试库，系统只读采集 SQLite schema 快照。
5. 只有人工批准后，流程草稿才能交给确定性执行器；审批、工具调用和结果会进入 AI 审计记录。

认证变量约定：

```json
{
  "AUTH_TYPE": "bearer",
  "TOKEN": "token-value"
}
```

Basic Auth 使用 `AUTH_TYPE`、`USERNAME`、`PASSWORD`。API Key 使用
`AUTH_TYPE=api_key`、`API_KEY` 和可选的 `API_KEY_HEADER`。
# 路线 A：外部测试 + 内部工艺脚本

从后端源码生成业务流程后，流程 JSON 使用 `process_script_version: 2.0`。每个 HTTP 外部动作可包含：

- `internal_checkpoints`：事务、写库、消息发布和外部依赖等内部工艺；
- `evidence`：源码文件与行号等静态证据；
- `observation`：数据库快照、运行轨迹等运行证据；
- `failure_branches`：异常、回滚和补偿分支；
- `invariants`：跨接口、跨数据库状态的一致性约束。

在“路线 A · 源码驱动测试”中点击“检查工艺完整性”可查看覆盖率和证据缺口。关键内部工艺只有静态推断、没有运行证据时，工作流即使接口返回成功也会显示 `inconclusive`，不会判定为通过。
